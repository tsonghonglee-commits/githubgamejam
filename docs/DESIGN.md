- **电脑版显示追加要求**：默认全屏，开启 4× MSAA 抗锯齿与垂直同步；仍使用 Godot 4.7.2 Compatibility。

- **速度来自世界运动**：初始速度也要有地面接缝、短标线、近景支架 / 反光片和横梁的可见流动；它们由实际累计路程驱动，随四档速度连续加快。HUD 边缘加速线只作少量辅助。不能新增换道、跳跃或自动躲避来代替当前玩法。

## 0.6 本轮反馈优先：v0.6.0 连续轻击与刀柄领刀（2026-11-04）

- **十二式轻击**：横切、纵劈、斜落、上挑、掠切与弧回等十二种具体刀路依次衔接，每轮十二刀不重复，相邻两刀不同；各式的切向、腕肘运动、收势及节奏均有区别。
- **每次按下响应**：独立左键按下立即出刀并提交该实体刀姿的有限刃腹窄线，不再用 130ms 冷却吞掉快速连按，也不延后排队。同一按下状态的重复 pressed 事件不重复出刀。轻击仍不奖励速度。
- **刀柄领刀**：将“刀柄处向着鼠标移动方向”具体实现为刀柄在移动方向前方、刀尖拖在后方；有向刃轴朝鼠标位移反向连续转动，取代此前近似垂直于鼠标且选择最近正负轴的处理。保留准确握点、慢划、曲线、反向与停鼠保姿，不牵动镜头 / FOV。
- **切口彩色发光体素**：细小体素从实际切除的体素 / 切口位置发出，沿切向、切面法向及深度向分散，使用多种颜色和发光材质；真实大块数据、再次切割及一次击杀结算保留。残骸再切也会产生细屑。
- **画面和性能复核**：先核对十二式连续动作、八方向 / 回拉的握柄关系与切口来源，再做正常战斗。细粒子采用批量绘制、容量与寿命限制，避免节点堆积及遮住切口。

刀柄领刀是本轮对用户表述的具体实现取法；此前“水平拖动自然稳定成竖刀”的记录均为旧行为。游戏名称、敌人密度和伤害等未定参数未升级为最终平衡要求。

## 0.5 本轮反馈优先：v0.5.0 太刀动作重建（2026-11-04）

- **动作连续性**：出鞘、普攻过冲、架刀、受力弹开和纳刀由同一把实体刀完成。取消模式切换时隐藏刀身 / 突然替换鞘柄，以及按下普攻先伤害、下一帧才显刀的错位。
- **自由拖刀接管现有姿态**：进入长斩从屏上真实刀柄位置、刀轴和景深倾角接管，不再为了回到准星扳动整把刀。鼠标保持刀柄中央握点；姿态与有效刃腹切口仍使用同一几何。停鼠保姿，不加镜头回正或 FOV 拉扯。
- **区分动作发力**：普攻使用快速切入、肘腕带出的过冲与回收；振刀使用主动迎击、碰刀压缩、反向卸力和重新架刀，空振与成功接触不同。保留按下立即普攻，不用延迟结算换取表面顺滑。
- **声音跟随相位**：出鞘咬口、运动破风、碰撞、斩断、收刀入鞘分开触发。停鼠不循环播空气声；普通擦伤、结构斩断和真实振刀接触具有不同反馈层级。
- **保持精确切割**：继续使用一个实际刃腹接触点的窄切口，取消整刀投影面积擦除的修复不回退。慢速、曲线、往返与退出前最后输入均保留；长斩命中反馈不能拉离握点。
- **用连续画面复核**：同一组真实鼠标事件分别录制 v0.4.2 与本版动作，检查切入 / 急停 / 回拉 / 切换 / 纳刀；之后另做正常难度战斗。定点演示与脚本通过不代表用户认可手感。

本段覆盖第 0.4 节“进入长斩强制把有效接触点反求回准星”的旧实现选择；其他精度与破坏规则继续有效。参考来源与本项目应用见第 15 节。

## 1. 用户已提出的游戏方向

- 类型：3D 第一人称跑酷 + 斩击。
- 体验目标：独特的美术风格、强烈的速度感和非常爽快的打击感。
- 游戏名称和故事背景尚未确定。单局采用短固定路线后接 Boss，击败 Boss 为通关目标。
- 技术基线：Godot 4.7.2 stable 标准版、GDScript、Compatibility。

## 2. 第一人称表现与操作

### 2.1 角色与太刀

- 不制作玩家身体模型，也不制作手部模型。
- 使用第一人称视角。
- 常态在画面右下角显示一把未出鞘的太刀（刀与刀鞘关系须在视觉上清晰）。
- 拔刀、挥砍、振刀、归鞘由武器本身的运动表现。
- 剑的外观与特效方向参考《合金装备崛起：复仇》中雷电、山姆的太刀与斩击气质。

### 2.2 已提出的输入规则

| 输入 | 行为 | 与速度的关系 |
| --- | --- | --- |
| 短按鼠标右键 | 短暂拔刀进行“振刀”，抵挡对向敌人的攻击 | 成功抵挡时，按完美程度获得不同的速度提升 |
| 短按鼠标左键 | 按下即拔刀并结算普通攻击，向光标处挥砍 | 普攻不会提升速度 |
| 长按并保持鼠标左键 | 保持拔刀，锁住进入时视角与 FOV 后进入慢动作；移动鼠标，进行类似水果忍者的轨迹斩击；拖动可提前进入 | 整个保持状态持续消耗速度，同时按 Shift 仍净耗速；耗到底提交最后刀路后自动收刀 |
| 持续按住 Shift | 持续提速 | 达到各速度阈值时升档；总计四个速度区间 |

“普攻不加速”不自动等同于“普攻耗速”；普攻是否存在成本尚未确定。
振刀窗口、精度等级和具体冷却数值仍可调试；本轮已采用按下普攻、约 0.13 秒长按或拖动进入长斩，退出前提交刀路。输入规则以第 0.1 节为准。

## 3. 奔跑、速度与档位

- 玩家始终处于奔跑状态。
- 包含不按 Shift 的初始档，总共四档，不是初始档外再加四档。
- 持续按住 Shift 会持续提速，到达对应速度阈值后自动进入更高档。
- 档位越高，玩家伤害 / 收益越高，死亡风险也越高。
- 速度必须通过实时可视化速度条显示，速度条上标注四个档位的区间。
- 振刀成功可以赚取速度，持续斩击会消耗速度，短按普攻不提供速度奖励。
- 第四档有速度上限，松开 Shift 后速度缓慢回落。各档具体边界、加减速率和振刀奖励通过原型调试。
- 自动前进、无法换道、常态有限转头已确定。本轮不加入跳跃、滑铲或墙跑控制。
- 速度耗到底后自动收刀；恢复后再次进入长斩的门槛属于调试参数。
- 初始速度与最低速度分开：v0.2 暂为 18 与 4，给初始长斩留出可消耗余量；长斩暂按 10/s 耗速，Shift 同按时净耗速 8/s。

## 4. 生命与结束

- 玩家有初始生命槽。
- 用户举例为五槽；五槽暂作初始调试候选值，不视为已锁定的平衡数值。
- 生命槽耗尽时角色死亡，游戏结束。
- 受击仅扣生命，不降低速度；死亡后可快速重开。
- 单次伤害与槽数的对应关系、受击保护时间和治疗规则尚未确定。原型先以每次普通伤害扣一槽验证。

## 5. 跑道、敌人与隐藏临界点

- 存在四条跑道。
- 敌人迎面冲来。
- 存在用于敌人伤害结算的隐藏临界点。
- 任意跑道的敌人漏过都会造成伤害；玩家不能换道。跑道决定敌人的视觉位置和覆盖宽度，不决定是否免于漏敌惩罚。

| 敌人 | 占道 | 用户已提出的攻击行为 | 对抗要求 |
| --- | --- | --- | --- |
| 普通怪 | 一道 | 到达隐藏临界点时，对玩家造成一次伤害 | 玩家可以攻击该敌人；近身攻击的振刀细节待定 |
| 肉盾怪 | 两道 | 到达隐藏临界点时，对玩家造成两次伤害 | 两次伤害的间隔、能否分别振刀、斩击如何打断待定 |
| 远程怪 | 一道 | 未到临界点时就向玩家射击 | 玩家可以通过斩击或振刀抵抗射击 |
| Boss | 四道 | 与玩家保持相对静止，持续释放造成伤害的技能 | 技能须设计为能通过斩击或振刀规避伤害 |

Boss 的“相对静止”指其与玩家保持相对位置，不代表全世界停止运动。
各类敌人的护甲、致命结构、攻击前摇、射击频率、击杀收益和出现节奏尚未确定。

## 6. 用户提出的美术与破坏方向

- 体素是用户倾向考虑的美术选型，目前尚未最终锁定。
- 希望利用块状结构，呈现敌人被砍成两半或变成碎屑的破坏效果。
- 用户认为体素风格适合 AI 辅助制作 3D 素材；实际制作质量和修改成本需要用样例验证。
- 太刀与刀光希望具有《合金装备崛起：复仇》中雷电 / 山姆的风格气质。
- 不因此预设必须实现完整体素世界、全场景破坏或任意模型的实时切割。

## 7. 原型中调试的剩余问题

1. **长短按响应**：本轮已改为按下即普攻、保持或拖动进入长斩，继续实玩调整阈值与视觉反馈。
2. **斩击空间**：本轮暂采用 32m，持续轨迹不设目标级切割黑窗；继续调试扫过体素的厚度、穿透量与性能。
3. **关键结构**：敌人的哪些核心、关节或躯干连接属于致命部位；高档如何提高装甲穿透和破坏量。
4. **慢动作计时**：世界、弹体和敌人攻击共同减速；输入、速度消耗和振刀冷却按实际时间推进，继续实玩检查切换边界。
5. **高档风险**：接敌时间、敌人组合和攻击节奏如何随档位产生压力；Boss 固定距离时如何保留足够反应时间。
6. **伤害与防御**：振刀时间精度、肉盾两段伤害与受击保护时间的关系，以及振刀是否影响敌人本体。
7. **流程平衡**：路线长度、敌人密度、得分与通关奖励、重开节奏。大方向已确定为固定路线后接 Boss。

## 8. 原型实现建议与调试方向

本节中与第 0 节重复的方向已经拍板；其余造型、表现和具体算法是原型实现建议。

### 8.1 核心体验与主题

建议把速度同时作为伤害依据、风险来源和可消耗资源：
奔跑 / Shift 提速 → 高档提高伤害与风险 → 振刀赚取速度 → 持续斩击花掉速度。

这可将 SHIFT 的按键、换档、攻防模式切换联系起来。主题诠释尚需在实际玩法中验证。
速度上限保持在第四档内，持续按 Shift 不会无限加速。
同时按 Shift 与斩击时净速度仍下降，确保持续斩击有成本；具体数值通过原型调试。
持续斩击耗到最低速度时自动收刀，恢复到一定速度后才能再次进入；恢复门槛待调试。

### 8.2 控制与战斗可读性

- 玩家自动前进且不能换道；常态鼠标有限转头，让四跑道的敌人位置保持可读。
- 长按斩击时锁住进入时的朝向和 FOV，鼠标驱动屏幕范围内的切割轨迹，并进入慢动作；保持最后刀路方向，不回正。
- 左键按下立即普攻；长按或拖动平滑进入轨迹斩击，取消等待松开才命中的延迟。
- 普攻与后续实际刀路共用真实体素破坏规则，重复扫过已删除的空格子不再产生伤害；同一敌人不重复结算击杀或得分。
- 慢速位移累计为刀路；连续命中不使用旧版目标级 65ms 黑窗。重建与采样的优化不能默默丢弃真实路径。
- 轨迹仅命中进入有效距离 / 深度窗口的敌人与弹体，避免从远处扫屏清空全部威胁；具体距离和提示尚需调试。
- 隐藏结算点可以不画线，但应通过敌人抬手、武器亮起和声音提示让玩家判断攻击时机。
- 肉盾的“两次伤害”可尝试有可辨识间隔的两段攻击，不把两次扣血藏在同一帧。
- 占道宽度用于描述覆盖范围，多个碰撞体不应意外重复结算伤害；肉盾的两次伤害应由明确的攻击规则触发。
- 四档速度条之外，以数字 / 罗马数字、升降档反馈辅助识别档位；颜色不作为唯一标记。

### 8.3 美术组合

建议尝试“块状机械敌人 + 工业高速通道 + 精细轮廓太刀”的组合。

- 敌人：大块装甲、清晰轮廓、少量发亮接缝 / 核心；体素结构集中服务肢解和碎裂。
- 场景：模块化工业通道、轨道、管线和大色块；避免背景细节盖过迎面敌人。
- 太刀：细长的低多边形机械刀身与刀鞘，强化刀刃和块状敌人的轮廓差异；不要求剑也使用粗体素。
- 配色候选：暗色环境、浅色装甲、青白刀光，少量橙红攻击预警。具体颜色需做实际画面验证。
- 整体造型与配色建立项目自己的辨识度，把参考作品用于刀光节奏、机械结构和出刀气势。

### 8.4 破坏与打击感

- 本轮以低分辨率动态体素敌人验证实际刀路破坏、关键部位切断与残骸分离；最终分辨率和碎屑预算待测。
- 第一刀命中、致命斩断与高档粉碎应有不同反馈；斩断需要保持敌人轮廓和切口的可读性。
- 大块残骸可短暂参与物理，小碎屑以简化动画 / 粒子表现；限制同屏数量和存活时间。
- 体素外观不等同于保留可修改的体素数据。规则体素可通过删除格子、重建新外露表面形成切口；任意三角网格剖切则另有切面封口问题。两条路线均需处理分离和碰撞更新。
- 命中反馈优先打磨刀光、切口、瞬间停顿、敌人受力、碎片方向、音效层次，再调整镜头冲击。
- 振刀成功需有独立的撞击声、火花、判定等级和可见速度跃升，建立“我靠操作赚到了速度”的反馈。
- 残骸须保留体素数据，可继续切分；死亡不把全部剩余实体一次性变成不可交互展示模型。
- 镜头震动和速度视野变化保持克制、提供强度设置；高速奔跑和鼠标切割本身已经具有较多画面运动。
- 长按斩击包含慢动作；慢动作如何影响移动、振刀窗口和速度消耗，需要统一计时规则。
- 若使用整体命中停顿，敌人、弹体和伤害判定计时须与玩家同步，避免玩家停住时危险仍然推进。

技术参考：[Godot 程序化几何文档](https://docs.godotengine.org/en/stable/tutorials/3d/procedural_geometry/index.html)。该文档说明常规程序化网格构造在 CPU 上运行，需实测本轮连续体素切割的成本。

### 8.5 敌人与 Boss 的首版方向

- 普通怪先验证一刀斩断、攻击预兆、振刀与接敌速度的关系。
- 远程怪可用少量清晰可见的飞行物，让斩击与振刀两种抵抗方式都能被练习。
- 肉盾先尝试双核心 / 分段装甲与两段可读攻击；具体破防规则仍待确定。
- Boss 先尝试两类招式：可振刀的近身冲击、可斩落的弹幕 / 核心攻击；每招清楚预告对应对策。
- Boss 阶段维持背景流动和速度条；高档风险可通过技能节奏体现，但需要保留足够的观察与反应时间。

### 8.6 最小可玩原型顺序

1. 四条敌人跑道、固定横向位置自动前进、有限转头、Shift 提速、四档速度条和生命槽。
2. 一种普通怪；右下太刀的拔出 / 归鞘、短按普攻、振刀分级加速。
3. 长按轨迹斩击、慢动作和耗速，验证与受限视角、Shift 的兼容。
4. 实际体素关键部位切断、分离与残骸效果，集中打磨连续斩杀与完美振刀的手感。
5. 扩充远程怪、肉盾怪，再加入只含少量招式的 Boss。
6. 完成固定路线后接 Boss、死亡快速重开与通关流程，再调整正式美术和提交版本。

第一轮先用战斗验证三种刀动作、实际体素切割和速度循环，再接入完整原型路线；本次已获授权开始编写原型代码。

### 9.2 PicaVoxel 公开源码可确认的机制

- Frame 保存体素数组；修改格子后标记受影响分块及必要的相邻分块，随后更新模型。
- 网格生成支持只生成可见表面、合并相邻面等方式，不要求一个体素对应一个场景物体。
- 示例 VolumeSplitter 使用六邻接搜索，将仍然相连的体素分为若干组，为每组生成独立体积。
- 破坏示例可把被删除的格子交给粒子系统表现，并限制批次粒子数量。

### 9.3 Teardown

- 作者说明每个 shape 保存稠密规则三维体素网格，模型可拆为多个 shape；同篇介绍的 8×8×8 稀疏分块属于下一代引擎，不能混称为 Teardown 的既有实现。
- 官方 API 区分刚体 body 与体素形状 shape，一个 body 可包含多个 shape。破坏可涉及删除体素、分离对象、建立新对象和调整关节。
- 作者确认渲染器沿射线遍历体素体积寻找表面；物理和破坏经过长期专门优化。
- 作者指出 Teardown 使用光追做环境遮蔽、软阴影、镜面遮蔽，但没有光线反弹式全局光照。
- 官方还提供碎屑粒子接口，不能把画面里所有小碎屑都理解为完整物理体素。

来源：[作者 2024 年总结](https://blog.voxagon.se/2024/12/29/year-summary.html)、[作者 2026 年开发日志](https://blog.voxagon.se/2026/03/13/teardown-multiplayer.html)、[官方 body / shape / 粒子 API](https://teardowngame.com/modding/api.html)、[作者本人技术采访](https://80.lv/articles/teardown-developer-breaks-down-multiplayer-and-voxel-destruction-tech)。尚未确认其具体连通域算法和碎片尺寸阈值，不把基础库实现推套给 Teardown。

### 9.4 对本项目的原型验证方向（已启动、待实测）

本轮先用一个敌人验证：保留小体积规则体素数据 → 刀轨迹删除穿过的格子 → 更新新外露表面 → 将断开的块分离 → 大块短暂物理、小碎屑视觉表现。
这种方案用于验证随刀路变化的阶梯状切口与关键结构判死；具体性能和视觉质量待实测。
优先让敌人拥有动态体素数据，武器和环境可保持普通模型；不需要先制作完整的可破坏世界或专用体素渲染器。
敌人造型优先考虑可切断的关节、腰部连接和清楚的装甲 / 核心结构。肉盾可使用更宽的轮廓与分段装甲，避免仅靠高密度大体积堆叠成本。
正式选型前需在本机验证单次切割耗时、连续长斩、多个敌人同时受击及残骸累计的表现；暂不承诺帧率或可承载数量。

## 10. v0.2 自测发现与前后对比（2026-11-03）

### 10.1 用户反馈与验证方式

用户在首版实玩后反馈手感差、体素切割不够自由、长斩不应回正，并要求开发方先自行模拟多轮发现问题。
首版的 37 项功能检查保留为历史记录；其中的自动路线通关使用脚本读取目标位置并调用切割，不覆盖真实鼠标操作链路，不能据此证明手感合格。

本轮先保存原版脚本快照，以相同 InputEvent 对象回放初始长按、侧视后长斩、慢速输入、快速往返、同屏多敌和接敌等场景，再对修订版比较。
基线与对比日志保存在本机被忽略的 `.local/audit-baseline-results.log` 和 `.local/audit-current-results.log`；边界脚本为 `.local/audit_boundary_replay.gd`。
这些是输入链路与行为观测，不等同于人工玩家对手感的认可。

### 10.2 基线问题与修订结果

| 场景 | 首版测得的问题 | v0.2 修订 / 复测 |
| --- | --- | --- |
| 侧视后进入长斩 | 朝向从约 16.50° 被拉回约 0.055° | 保留进入时朝向；同一回放前后均为约 16.50°，长斩时 FOV 和镜头位置保持稳定 |
| 小位移、高频鼠标事件 | 20 个 3px 事件移动光标约 63px，但没有刀路；20 个 5px 事件只剩 12 段 | 两组均保留 20 段实际轨迹，慢速位移按累计路径处理 |
| 初始状态直接长按 | 基速 12 时不能进入长斩；保持左键再按 Shift 到速度 23 仍锁住 | 初始速度与最低速度拆开为 18 / 4，直接长按可进入；拖动可提前进入 |
| 短按普攻 | 按住 100ms 期间切割次数为 0，松开才变为 1 | 按下即切割，松开不补发第二次普攻 |
| 可见的远处目标 | 对约 23m 的可见目标划过，切割次数为 0；16m 硬门槛没有提示 | 原型范围扩至 32m，约 23m 的同场景可切；目标增加可切状态与接敌倒计时 |
| 快速往返切割 | 第二刀在 8ms 后划回目标仍不生效，等约 90ms 后第三刀才生效 | 去除持续斩击的目标级 65ms 黑窗；同场景第二刀正常生效 |
| 同帧两道攻击 | 一次振刀后，一击被挡，另一击仍扣血，成功提示与扣血同时发生 | 同一短振刀窗口可挡同步攻击，生命保持 5；速度只奖励一次 |
| 隐藏接敌点 | 敌人在约 4.5m、仍完整可见时扣血，缺少清楚的倒计时 | 保留接敌结算规则，增加目标倒计时与提示；是否足够直观仍待人工实玩 |

首版最高速时，从可切距离 16m 到伤害点 4.5m 的有效时间约 0.213 秒，而旧长按入口需要 0.19 秒。这使首次接敌的容错极小。v0.2 扩大范围并缩短入口时间，仍需正常难度实玩检查节奏。

另一个切割自由度问题是首版死亡后残骸失去体素数据，不能继续斩切。v0.2 保留残骸格子与连通结构，可反复切分；片数预算耗尽时保留未分离实体，避免未切中的大块直接消失。

### 10.3 补充边界

- **最后刀路提交**：松开左键和右键打断均先消费待处理刀路。补测曾发现速度从约 4.083 降到最低 4 时，30px 刀路被直接清空；现已改为耗尽前先提交，复测通过。

### 15.2 动作与接触

太刀以虚拟肘、前臂和腕部共同产生刀柄弧线，肘部位置使用非均匀时间 Hermite 曲线，旋转使用按关键帧时间计算的四元数曲线，避免每个姿势点都停住再加速。普攻按下立即给出接触姿态；随后约 38ms 快速通过、80ms 到达横向过冲、145ms 腕部回收、230ms 就绪。短促窄金属残影连接出鞘，不参与伤害。连点接触姿态继承上一刀部分腕部方向和景深变化，不反复播放已经完成的拔刀音。

振刀约 80ms 迎击、120ms 架稳；真实接触另触发约 28ms 受压、95ms 弹开、180ms 回架。成功火花位置取实际刃腹，而非固定屏幕中央；空振不产生碰刀撞击。纳刀约 440ms，前 270ms 清空刀尖路径并翻腕对口，后 170ms 沿实体鞘轴插到底，同一把实体刀持续绘制。出刀时刀鞘自然下沉让出挥斩弧线，再在对口阶段抬回；刀鞘运动不牵动长斩握点。

刀身改为钢质宽面、实际锐斜刃和暗刀背三组几何法线 / 材质，减少恒亮刃条，让转腕时的分面和高光可见。实画面复核发现第三稿面片绕序导致朝镜头宽面被剔除、像黑棍，已按 Godot 的顺时针正面规则修正；只通过脚本检查无法发现这一画面缺陷。

长斩入口保存实际握点、刀轴、景深和倾斜。鼠标控制刀柄中央，停鼠保留刀轴；扭转弹簧仅沿刀身轴改变高光，不改变中心线、握点和切口。3D 倾斜的投影及反解由同一几何函数给出。进入时完整保存镜头旋转（包括当前受击滚转）、位置和 FOV，长斩中不再扳回零滚转。

声音分为出鞘、破风、纳刀、迎击举刀、卸刀、擦伤、结构斩断和碰刀。持刀破风来自实际运动，停止不会循环播放；强接触短暂压低空气层。HUD 只保留一条短薄刀路和真实接触位置的小闪，世界火花沿切向分散，寿命与透明度及时收束，避免慢动作下长时间堵住目标。

### 17.2 轻击动作与长斩接管

保留十二式和每次独立 press 立即结算实体有限刃线，扩大肩肘位移、腕部旋转、景深和远侧过冲。主要驱动在前几个显示帧完成，随后沿出刀方向制动、在远侧保留张力，避免急速弹回中央竖刀。首稿将主切姿态节点设在约 17ms（各式约 14–22ms）、大幅甩开 / 过冲节点设在约 50ms（约 42–60ms），整体约 250–320ms；实际录制后主切近乎只有一帧、刀面朝向显暗，被主动否决。最终主切调整到约 24–30ms、甩开到约 60–78ms，整体时长保持；早段刀身靠近镜头，绕实体长轴有限展面、提高普通轻击钢面亮度，后段在远侧露回少量刃段，不回中央。这些都是本项目自定动画关键帧，未推迟按下当帧的伤害，更不是商业作品公布的时值。快速新点击可以继续承接余势，不要求先播完恢复动画。

刀尖 / 刀身允许出屏，柄部只保留能够接管的范围。每一式的中途姿态均须能够进入长斩：读取当时真实刀柄、刀尖、有向刀轴和景深，下一帧准确握点，不把整刀扳回中性姿势。实际切割仍是原来的有限刃腹窄线；扩大视觉动作不等于扩大伤害 mask。普通接触的短暂受阻和振刀反作用分开，长斩命中仍继续处理刀路与实际耗速。

### 17.3 实际奔跑流动与声音

v0.6 大面积地面、连续道线和侧墙相对静止，少量远柱与地面短标记难以说明基础速度。本轮在地面材质加入接缝、颗粒和分段标线，由累计 `speed × sim_dt` 的实际路程驱动；同一路程驱动 x 约 ±4.9m 的近景短支架 / 反光片及上方横梁。近物迅速划过画面边缘，远处仍保留稳定的敌人识别区域。批量几何使用 MultiMesh，地面使用 Compatibility 可用的程序材质。

基础 18 与高速 60 都有流动，强度随实际速度连续变化，不仅切换档位时改数字。普通奔跑相机可有轻微落脚起伏 / 交替侧摆和约 78→90 的速度 FOV；长斩进入后完整锁住当时位置、旋转及 FOV。脚步与普通镜头共用两步循环相位；每个落脚推进一次，左右交替。F4 保持静止实验场，不制造前进光流；暂停和命中停顿不推进路程。

声音由两层循环风床和两路金属落脚组成，使用原创立体声 PCM 合成；它们独立于原有 22 个战斗声道。低层表示风压，高层表示速度气流，随 `speed × world_scale` 调整音量与音高；脚步按实际世界路程触发，不按真实秒数固定敲击。慢动作放慢路程和落脚，风床随有效速度衰减；刀声和碰撞仍实时。强接触短暂压低风声，蓄势声也得到短暂空间，防止环境声掩盖攻击信号。风床 / 脚步的逻辑步相、声道独立性与 PCM 余量已检查，不能据此声称主观听感已获认可。

### 17.4 暖色金属火花

切口源仍取实际移除格及切面，向切面法向两侧形成不均匀喷扇，并混入切向和少量景深散射。暖白热亮点迅速冷却为金黄、橙红；拉长方向跟随粒子当前速度，使用窄亮核和短尾，取代青 / 品红等六色方块及大柔晕。Compatibility 下由批量几何 / 材质实现，不依赖更换渲染器或全屏泛光。

首录即使达到 44 颗峰值仍细暗，被主动拒收。先修正真实迎镜切格来源及显示宽度；随后单颗 GPU 对照进一步确认：本机 4.7.2 Compatibility 的 unshaded 分支忽略 EMISSION，旧尾丝全空、热头灰棕，将热色亮度改由 ALBEDO 输出才清亮。生产热头 / 尾丝现均由 ALBEDO 输出，尾丝热色增益 1.7，debug 的 `emission` 保留为 0，`brightness_output` 为 `unshaded_albedo`；没有靠提高粒子数或寿命掩盖。

最终基础亮点宽约 2.8–7.2mm，并按距离保留约 1.10–1.40px 热头、1.60–1.90px 尾片的显示尺度，尾片中约 62% 保持热中轴；约四分之一为错落长针，尾长约 6.5–55cm。约 75% 从实际切格的迎镜表面采样，微量脱面后仍接受正常深度遮挡。每次 14–52 颗、寿命 0.14–0.32 个世界秒，每敌人 192 槽 / 全局 768 槽，未增加数量和寿命预算。

火花只提供切口反馈，不参与切割、判死或计分，不替代可继续切割的大块。世界停顿冻结位置和寿命，迎面奔跑流只施加一次，残骸再切仍从新切口产生火花。最终实际首切 33 / 100ms、再切 100 / 200ms 画面已查看，暖白、金黄和橙红细丝清晰四散；这只记录实际可见性与造型复核，不代表用户已认可打击感。

## 20. 最终渲染与四类敌人重设计方案（2026-11-05，建议阶段）

### 20.1 目标与当前差距

目标是有独立辨识度、能够持续高速战斗的高品质体素画面。用户确认了品质目标和怪物重设计；本节的场景题材、色彩、造型、预算和技术取舍是建议，尚未变成新的实现约束。

对照本版正常奔跑、长斩、首次切断和 Boss 实机帧，可见主要差距：

1. 敌人的大块白壳缺少材质区别，亮面经常失去转折；外壳、关节、内部结构与切面没有形成稳定层级。
2. 场景主要依靠同形门架和连续色带，近 / 中 / 远景节奏单一；大面积统一环境补光削弱接触阴影与金属高光。
3. 完整体素身体过于简化，很多方块特征只在被切断后才出现；需要加强完整轮廓、装甲分区和内部结构，而非整体把格子缩小。
4. v0.7.1 增强了切割爆发，随后用户仍指出火花缺少体素形态；后续须让真实体积与平时环境形成反差，敌人动作、刀身和切口必须保持可读，HUD 也不能遮住自由握点。

这是实际画面观察，不是对商业作品算法的推断或 GPU 性能结论。

### 20.2 推荐的视觉方向

建议以**夜间炼钢厂中的机械武者**作为第一套可评审方向：石墨色钢结构、局部旧象牙白涂层、暴露的铜色传动件，冷蓝夜光与局部炉火暖光形成层次。玩家刀刃保留冷白金属亮边，核心和预警使用有限、稳定的功能色；金橙火花承担接触时的亮度峰值。避免让全部表面和连续道边同时自发光。

建筑保留体素的大块面和台阶式轮廓，在两侧加入不同尺度的管线、检修平台、设备与远处炉架地标；四道正面战斗区保持相对干净。可用开阔高架、低顶检修段、炉区侧光构成视觉节奏，不因此增加换道、跳跃、跑墙或转向玩法。

地面以粗糙钢板 / 混凝土为主，少量湿润区域反射宽大的静态灯色，避免整条路都成为镜面。刀、敌人、环境应在静帧里成立，高速运动时仍能分清武器朝向；不靠强景深、糊屏、镜头污渍或持续白闪掩盖素材问题。

Ghostrunner 开发者介绍了早期先制作视觉模板与标志场景，再统一布景和灯光的工作方式，也强调高速关卡可读性；本项目采用这一制作顺序，玩法仍遵循自己的四道迎敌规则。[开发者访谈](https://www.unrealengine.com/developer-interviews/ghostrunner-is-one-of-the-best-looking-coolest-cyberpunk-games-on-the-market)

### 20.3 四类敌人：先轮廓，再材料，再细节

怪物重设计是用户明确要求。以下具体机械武者造型为概念提案，名字只描述功能；四类占道、漏敌伤害与已确认战斗规则继续保留。

| 类型 | 造型建议 | 远处识别 / 动作 | 切割必须对应的结构 |
| --- | --- | --- | --- |
| 普通怪，占一道 | 小型尖角面甲、偏瘦前倾躯干、不对称肩甲，单手长刃 | 肩、肘、刀尖形成清楚斜线，蓄势后迎面挥击 | 持刀手、颈腰连接与内部骨架可真实切断；刀不能脱离手继续攻击 |
| 肉盾怪，占两道 | 宽阔梯形肩背、低重心厚装甲，双手各持方形重锤 | 两只锤与两段蓄势分别可见，轮廓明显比普通怪宽 | 两臂独立，保留左右手对应攻击取消；厚外壳与承重连接可辨 |
| 远程怪，占一道 | 高瘦窄身、长机械腿、小型传感头、可见手持重枪 | 枪体和枪口成为主要轮廓，充能沿枪体向枪口集中 | 明确哪只手负责发弹；切掉该手取消开火，不能把枪藏进不可切背包 |
| Boss，占四道 | 巨型双臂铠甲、宽炉架式肩背、凹入装甲内的炉心，刀炮工具与手相连 | 体量和双臂动作覆盖四道；核心有真实深度，避免前方漂浮大光球 | 保留逐手检查发弹 / 伤害，所有技能可斩 / 振刀防御；核心真实切断后进入残骸收尾 |

四者共用材料家族，但不共用简单人形比例后只放大 / 换色。普通怪强调锐与快，肉盾强调宽与重，远程强调窄与瞄准，Boss 强调巨大双臂与炉心压迫感。概念稿的工具细节需服从原攻击判定，不视为已经批准新增技能。

后续模型要提供真实体素占用、材料 ID、颈腰 / 核心连接标签和武器手绑定；外壳、内部骨架与核心都随实际切块分离并继承材质。不能用一层完整的漂亮外壳网格罩住旧体素，造成外观、受击和切口不一致。先保留现有切割精度，在可见轮廓上改善设计；小装饰不能形成额外不可切的实体装甲。

Teardown 作者公开的材料系统同时保存颜色、粗糙度、反射率等，碎块继承原材料；可借鉴“破坏前后材质一致”的原则。[作者开发日志](https://blog.voxagon.se/2020/12/03/spraycan.html) Clone Drone 官方确认其身体任意部位可精确切除，但并未公开一套可直接复用的完整灯光参数。[官方作品说明](https://clonedroneinthedangerzone.com/press/clone_drone_in_the_danger_zone/)

### 20.4 材质、光照与切面

优先建立一组能在同一灯光下分清的材料：旧涂漆、粗糙铸钢、磨亮刀刃、暗橡胶关节、铜色内部件、发光核心。用受控的粗糙度 / 金属度和一致的边缘磨损表达材质，避免给每个体素随机撒噪声。大块装甲保持清楚平面，只对重要轮廓做适度边缘处理，不把所有方块磨成圆糖块。

降低当前均匀补光对形体的冲淡，建立一个清楚主光、适度冷色填光和局部暖色工作灯。先固定曝光，比较色调映射，确保白漆有层次、刀面不因模式切换突然变暗。补足脚底接触、关节缝隙与切面深度；少量 SSAO / Glow 辅助，炽热体素屑的厚度和面差仍保持清晰。

切断反馈建议形成三个阶段：真实刃线接触，结构断开的瞬间峰值，以及能看懂材质和内部结构的大块分离。新切面可短暂发热后冷却，但颜色变化必须属于实际新暴露面；关闭火花后也应看得出断在何处。高强度接触可共用少量短时无阴影灯，不为每颗火花挂实时灯；世界停顿下相关效果时间仍遵循既定规则。

### 20.5 Godot 4.7.2 路线与移动场景边界

保持现有 Godot 4.7.2 标准版 / GDScript / Compatibility，先用现有路线完成样片。4.7 的 Compatibility 已支持简化 SSAO、Glow 和反射探针，不能沿用旧版“完全不支持”的说法；SSAO / Glow 的控制能力也不能直接等同 Forward+。[官方特性表](https://docs.godotengine.org/en/4.7/tutorials/rendering/renderers.html)、[环境与后处理说明](https://docs.godotengine.org/en/4.7/tutorials/3d/environment_and_post_processing.html)

| 可先做 | 需要独立小样验证 | 不作为当前默认承诺 |
| --- | --- | --- |
| 实时主光 / 近景阴影、环境反射基色、材料层级、固定曝光、少量 SSAO / Glow、保留 4× MSAA | 移动模块的光照贴图与动态物体探针采样；反射捕获更新与模块循环接缝 | SSR、实时 VoxelGI / SDFGI、体积雾、TAA / FSR2、自动曝光或完整 HDR 管线；不直接切换渲染器 |

当前大部分建筑和近景批次每帧向镜头平移 / 循环，相机主要留在模拟原点；`main.tscn` 的结构主要由运行时代码生成。故“给静态关卡烘焙一次”不能直接套用。第一版可在现有坐标体系内改善实时灯光、材质和轻量后处理，不为画质工作重写玩家 / 敌人运动。

尤其不能把 `UPDATE_ONCE` 探针挂到每个移动模块后认为成本只有一次：对应版本实现会在探针变换时标脏并请求捕获。固定探针也可能与滚动建筑反射不同步。[4.7.2 光照存储源码](https://github.com/godotengine/godot/blob/ed1daf0bf001b61586d9930840f2f1394092c079/drivers/gles3/storage/light_storage.cpp)

光照贴图随 UV 的移动与动态物体在烘焙体积中采样不是同一件事；只移动网格会有采样错位风险，连体积移动又需检查更新成本和模块边界。动态敌人与残骸可以接收已烘焙间接光，但切碎不会反向重烘焙场景遮挡 / 反弹光。[动态物体与探针说明](https://docs.godotengine.org/en/4.7/tutorials/3d/global_illumination/using_lightmap_gi.html#dynamic-objects)

若研究烘焙，先将一小段几何保存为可编辑场景并提供 UV2。当前本机 `BoxMesh.add_uv2` 属性探针能生成 UV2，不使用“所有 PrimitiveMesh 都不能烘焙”的旧结论。[PrimitiveMesh 文档](https://docs.godotengine.org/en/4.7/classes/class_primitivemesh.html) 最小测试只需两个相邻移动块、一个敌人、两块残骸，经过平移、回收、命中停顿后检查受光、接缝和成本，再决定是否推广。

### 20.6 建议实施顺序

当前先完成第 21 节的装甲 / 火花修复、精度复核与正常战斗，随后推进以下建议流程。

1. **材料与敌人样品**：同一灯光下做一把刀、一个普通怪和一块可切墙板，确定白漆 / 合金 / 铜内构的层级；同时修饰钢面明暗过渡，不改握点与伤害。
2. **30 秒可玩视觉样段**：做两到三组有区别的环境构图与一个远景地标，完成近景运动、主光、贴地阴影、粗糙度和受控后处理。由这个样段确定最终美术方向，而非先铺满整关。
3. **扩展四类敌人**：按概念的不同轮廓制作真实可切模型与对应武器动作；检查占道、持武器手被切后的取消、核心切断、残骸再切与得分。
4. **光照空间小样**：另测移动烘焙块和反射更新，按结果决定局部采用；明确需要当前路线外的效果时，才将同场景 Forward+ 对照列为待拍板事项。
5. **整局画面与负载**：通过样段后扩展 180 秒流程，覆盖四档、连续斩杀、火花满载、Boss 双臂攻击和大量残骸，持续对照已归档原型的操控规则。

### 20.7 样片验收与性能建议

画面验收同时看静帧、连续运动和正常输入：低档与第四档、敌人 20–32m 蓄势 / 接触、首斩 0 / 33 / 100 / 250 / 550ms、长斩停鼠 / 回拉、Boss 与再切。中心敌人轮廓和实际武器姿态要清楚；临时关闭特效、降低饱和度后也能分辨主体和空间。UI 保留实时速度条与四档标注，并继续避让自由握点。

### 21.1 反馈、根因与修正

旧版确实删除了真实体素并触发连通断开，但其单次穿透预算相对关键连接过大：肉盾颈部只有三层，Boss 颈部四层，一次切割就可能贯穿。当前按四档对应 power 调整每个命中材料柱的层深预算：

| 重型 | v0.7.1：I / II / III / IV | v0.7.2：I / II / III / IV |
| --- | --- | --- |
| 肉盾 tank | 4 / 4 / 5 / 6 层 | 1 / 2 / 2 / 3 层 |
| Boss | 3 / 4 / 4 / 5 层 | 1 / 1 / 2 / 2 层 |

表中是每个实际命中材料柱的穿透上限，不是单击总去格数、生命值或固定击杀刀数。肉盾可见颈部连接另外由三层加厚为五层，增加 12 个真实体素；Boss 颈部保持原四层。切割从该部位当前姿态的迎镜存活层开始，若完整前层未被窄刃线命中，就停止该柱，不跳过前层挖后方核心。重复刀路仍实际去除存活材料，最终能切断连接；普通怪及原有输入 / 镜头规则不以此改成免死保护。

### 21.2 有体积的炽热体素屑

主火花改为真实 `BoxMesh` 立方体 / 短长方体，基边约 25–90mm，长短轴比小于约 2.2；随机三维初姿与约 12–34rad/s 翻滚，硬面存在暖白热面、金橙侧面和逐渐冷却的暗面。主块不沿速度拉成长针，也不朝镜头压成薄片。少数颗粒带短间隔、随模拟时间断续的小方块尾点，原先 1.3–2.4m 的长 Quad 针尾已移除；不使用圆 halo 或随机彩虹色。

猛烈双侧喷射与少量野散保留，延续擦伤 / 首次 sever / debris 再切分类。寿命仍约 0.065–0.22 世界秒，192 本地 / 768 全局逻辑槽；满载只替换本敌人的冷旧颗粒。随机翻滚、冷却和尾点节奏与位置一起接受世界冻结，奔跑流只施加一次。热亮通过本机 Compatibility 的 unshaded `ALBEDO` 输出，保留深度遮挡和真实切格迎镜表面来源。火花不参与伤害 / 判死 / 计分，不替代真实可再切大块。

旧调试字段保留，但 `shape` 改为 `tumbling_voxel_blocks`，`length_*` 表示主块最长边，新增三维尺寸 / 姿态 / 转速等信息。旧版“宽度小于 1cm、长宽比大于 8”的针形检查已不适用于本轮，不能为了旧断言把方块重新压细。

### 26.1 共面几何与最小修正

`scripts/katana_view.gd` 的 `_make_grip` 实际以 `direction=-1.0` 创建刀柄。钢镡尺寸为 `(0.098, 0.015, 0.05)`、中心为原点；象牙饰片尺寸为 `(0.065, 0.002, 0.041)`，原中心为 `(0, direction * 0.0065, 0)`。因此两者朝柄侧的外表面都在 `y=-0.0075`，重叠覆盖 `x∈[-0.0325,0.0325]`、`z∈[-0.0205,0.0205]`。它们同属实体刀节点，停刀姿态下该面朝向相机，微小姿态变化即可暴露深度争夺。
